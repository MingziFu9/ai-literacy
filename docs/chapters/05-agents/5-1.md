# 5.1 智能体概述 {#51}

!!! info "学前导读"

    聊天机器人只会“说”，智能体还会“做”。本节是全章的基础，回答三个问题：智能体是怎么一步步发展来的？它和大模型有什么区别？它由哪几部分组成？

    重点是 5.1.3 节的“四大支柱”和 ReAct 循环。看完后，你应该能看懂任何一个智能体产品“背后在干什么”。

## 5.1.1 历史发展 {#511}

智能体并不是一夜之间出现的，而是人工智能几十年探索的结果。大致可以分为三个阶段。

**1. 规则式智能体（20 世纪 60 年代—21 世纪初）**

代表：ELIZA、专家系统、微软 Office 里的“大眼夹”助手。程序员把人的知识写成成千上万条“如果……就……”的规则。

- **ELIZA（1966）**：最早的聊天机器人之一（详见 3.1.1 节）。它只靠关键词脚本，却让不少用户对它产生了情感依赖，这种现象后来被称为“ELIZA 效应”：人们倾向于把简单程序的行为过度解读为具有人的智能和情感。这也提醒我们，今天的大模型智能体同样容易被过度信任。
- **专家系统（20 世纪 70—80 年代）**：如用于血液感染诊断和抗生素推荐的 MYCIN（见 1.2 节）。它由庞大的“知识库”和“推理机”组成，在窄领域表现不错，但遇到了“知识获取瓶颈”：专家很难把经验都说成明确的规则。而且它很脆弱，一遇到规则之外的情况就束手无策。

**2. 学习式智能体（2011—2022 年）**

代表：Siri 等语音助手、AlphaGo、OpenAI Five。AI 开始从数据中学习规律，而不是依赖人写规则。

- **语音助手**：能识别用户的意图（如“定闹钟”）和关键信息（如“明早 7 点”），但本质上是“一问一答”，没有长期记忆，也不会规划复杂任务。
- **强化学习智能体**：AlphaGo 和 OpenAI Five 分别在围棋和电子游戏《Dota 2》中战胜了人类顶尖选手。但它们的能力被局限在规则明确的“封闭环境”里：把 AlphaGo 搬进厨房，它连鸡蛋都不会打。

**3. 大模型驱动的智能体（2023 年至今）**

代表：AutoGPT、斯坦福“AI 小镇”（Generative Agents）、Devin（AI 程序员），以及各种 AI 编程工具和“深度研究”功能。

- **原理**：用大模型作为通用的“大脑”，让它理解目标、规划步骤、调用工具。
- **特征**：有一定的**自主性**。你给出目标，它会自己查资料、写代码、发现错误再修改。

但要看到它的局限：早期的 AutoGPT 常常陷入兜圈子、重复同一个动作的循环；今天的智能体在长任务中仍然会跑偏、出错，需要人来设定边界和检查结果。

!!! question "讨论任务 5-1 规则还是学习？"
    在自动驾驶领域，一直有“规则派”（把交通规则、驾驶策略写成程序）和“端到端派”（让 AI 看大量驾驶视频自己学开车）的争论。你认为哪一种路径更安全？各自的风险在哪里？

## 5.1.2 智能体和大模型有什么不同 {#512}

和困在“对话框”里的大模型不同，智能体能接任务、拆步骤、执行动作。以“帮我订一张明天去北京的机票”为例：

表 5-1 大模型与智能体的行为模式对比
{ .tab-caption }

| 维度 | 大模型（只聊天） | 智能体 |
|---|---|---|
| 角色定位 | 咨询师：给建议 | 办事员：动手做 |
| 回复内容 | “你可以在购票 App 上查询，明天北京方向的航班通常较多……” | “查到明天上午 9:30 的航班，经济舱 600 元。是否确认预订？确认后我会跳转到支付页面，由你本人付款。” |
| 核心能力 | 理解、生成、推理 | 在此基础上加上工具调用、任务拆解、记住进度 |
| 工作方式 | 预测下一个词 | 反复执行“思考—行动—观察”的循环 |
| 局限 | 可能编造航班；不知道实时票价；不能真的下单 | 依赖外部工具是否可靠；可能误操作造成损失，所以付款等关键步骤必须由人确认 |

**结论**：如果把大模型比作“大脑”，智能体就是给大脑加上了“感官”（感知环境）和“手脚”（调用工具）。

## 5.1.3 核心架构：四大支柱 {#513}

2023 年，当时在 OpenAI 负责应用 AI 研究的翁荔（Lilian Weng）在博客文章中把大模型智能体概括为几个组成部分。这一概括被广泛引用，常写成：

**智能体 = 大模型（大脑）+ 规划 + 记忆 + 工具使用**

![图 5-2 AI Agent 的架构](images/fig5-2.png){ loading=lazy }

图 5-2 AI Agent 的架构
{ .fig-caption }

### 1. 大脑（大模型）

大模型是智能体的核心推理引擎，负责理解意图、做出判断、生成文字。智能体还需要“感知”环境：

- **数字环境**：在电脑里，智能体通过读取网页结构、程序接口返回的数据、屏幕截图来“看”。例如，它能“看到”网页上的“提交”按钮在哪里。
- **物理环境**：机器人通过摄像头、麦克风、力传感器感知世界（见 5.4 节）。

### 2. 记忆（Memory）

借用认知科学的说法，智能体的记忆可以分为：

- **短期记忆**：就是大模型的上下文窗口，存放当前这次对话的内容。开启新对话，它就“忘”了。
- **长期记忆**：把重要信息存进外部的数据库（常用 3.6 节讲过的向量数据库），以后需要时再检索出来。比如几周前你说过的偏好、一个长任务做到了哪一步。

!!! example "深度解析：智能体怎样“记住你”"
    - **提炼**：智能体不会把聊天记录原样存起来，而是让大模型定期提炼要点。你说“我今天吃了牛肉面，不太好吃”，它提炼为“用户不太喜欢牛肉面”，写入长期记忆。
    - **调用**：下次你让它推荐午饭时，它检索到这条记忆：“上次您说牛肉面不太合口味，今天试试鸡汤饭？”

    **和 3.6 节 RAG 的区别**：RAG 侧重“外部知识”（回答专业问题），智能体的记忆侧重“状态”（记住你是谁、任务做到哪一步）。两者用的技术相近。

    **隐私提醒**：智能体记住的越多，越懂你，泄露的风险也越大。好的产品会让你查看、修改和删除它记住的内容，你也应该定期检查。

!!! example "案例 5-1 长上下文与智能体（企业公布）"
    除了外接数据库，另一条思路是把上下文窗口做得足够长。月之暗面的 Kimi 在 2023 年 10 月推出时支持约 20 万汉字的上下文，2024 年 3 月开始内测 200 万字（见 3.4 节）。据其介绍，用户可以一次上传多份财报，让它提取关键指标并汇总成对比表。

    长上下文让很多任务不必切碎文档再检索，但它不能完全代替外部记忆：上下文越长，费用越高，而且模型对长文本**中间部分**的信息容易遗漏（体验 3-2 中你可能已经发现了）。

### 3. 规划（Planning）

第 3 章的思维链是让 AI“想一步说一步”。在智能体里，规划意味着“想清楚再动手、边做边调整”。

**模式一：ReAct（推理 + 行动）**

这是最经典的智能体工作方式：只要任务没完成，就重复“思考（Reason）→ 行动（Act）→ 观察（Observe）”。

> **用户**：我明天去上海出差，帮我查一下天气，并推荐穿搭。
>
> **思考 1**：需要明天上海的天气，我自己不知道，应该调用天气工具。
>
> **行动 1**：查询天气（城市 = 上海，日期 = 明天）
>
> **观察 1**：工具返回：中雨，15～20 ℃。
>
> **思考 2**：有雨，气温偏低，应建议带伞、穿薄外套。信息够了，可以回答。
>
> **回答**：明天上海中雨，气温 15～20 ℃，建议带伞，穿一件薄外套……

**模式二：先计划再执行（Plan-and-Solve）**

任务太复杂时（如“写一个贪吃蛇小游戏”），走一步看一步容易迷失方向。这时先列出完整的待办清单，再逐项完成：① 设计界面；② 写蛇的移动；③ 写食物的生成；④ 写碰撞检测；⑤ 合并测试。

**模式三：反思（Reflection）**

智能体会根据结果“复盘”。例如程序运行报错，它读到错误信息后反思：“我忘了导入需要的工具库，应该在开头加上，再运行一次。”反思让智能体能自己纠正一部分错误，但它也可能“反思”错方向，所以重要结果仍要人来检查。

### 4. 工具（Tool Use）

工具让智能体从“思考者”变成“行动者”。

**函数调用（Function Calling）**

开发者事先告诉大模型有哪些工具、每个工具需要什么参数。大模型判断需要时，不直接回答，而是输出一段结构化的“调用指令”（通常是 JSON 格式），由程序去真正执行，再把结果交还给大模型：

> 用户：查询北京天气 → 模型输出：`get_weather(city="北京")` → 程序执行，返回：`{"temp": "15℃"}` → 模型回答：北京现在 15 ℃。

注意：大模型自己并不“执行”任何操作，它只是提出调用请求，真正动手的是程序。这也是我们能在中间加上“人来确认”这道关口的原因。

**模型上下文协议（MCP）**

- **痛点**：以前每家大模型连接外部工具的方式都不一样，同一个工具要为不同的模型各写一套对接代码。
- **方案**：Anthropic 在 2024 年 11 月提出 MCP，可以把它理解为 AI 时代的“USB 接口”：工具按 MCP 标准做好一次，支持 MCP 的各种 AI 应用都能接入。2025 年，OpenAI、谷歌等相继支持 MCP；同年 12 月，MCP 被捐赠给 Linux 基金会旗下新成立的智能体 AI 基金会（Agentic AI Foundation），成为中立的开放标准。国内的很多大模型平台和开发工具也已支持 MCP。

**两条设计原则**

- **说明要写清楚**：工具的描述要清楚说明“什么时候该用我”。比如计算器工具写明“用于需要精确计算的数学题”，否则大模型可能自己“心算”而出错。
- **人在回路**（Human-in-the-Loop）：对于转账、删除文件、发送邮件等不可撤销的操作，智能体必须暂停，等人确认后再执行。

**常见工具**：搜索引擎和数据库（获取实时信息）；代码解释器和计算器（精确计算、处理数据）；邮件、日历、订单系统（办理事务）；图像和语音识别（感知多模态信息）；文件读写和程序运行环境（操作电脑）。

!!! question "深度思考 5-1 中文屋与智能体"
    哲学家约翰·塞尔（John Searle）提出过“中文屋”思想实验：一个不懂中文的人待在房间里，按照一本厚厚的规则书，完美地回答了门外递进来的中文纸条。这能说明他“理解”中文吗？

    智能体表现得再像人，它是否只是一个高效的“中文屋”？它有“意识”吗？请谈谈你的看法。

## 5.1.4 主要类型与应用场景 {#514}

**1. 生态定位**

可以把 AI 产业想象成一座三层金字塔：

- **第一层 基础层**：算力（GPU 等芯片）和数据，是“燃料”。
- **第二层 模型层**：各种大模型，具备通用的理解和推理能力，但本身只能“想”和“说”。
- **第三层 应用层**：智能体，利用模型层的能力，通过工具去完成真实的任务。

![图 5-3 AI 能力金字塔](images/fig5-3.png){ loading=lazy }

图 5-3 AI 能力金字塔
{ .fig-caption }

**2. 三大类型**

- **单一智能体**：由一个“大脑”独立完成任务。如 AutoGPT：给它目标“帮我开一家网上花店”，它会尝试查询花价、写文案、搭网页。优点是简单，适合步骤清楚的任务；缺点是任务一复杂就容易顾此失彼。
- **多智能体系统**：多个智能体扮演不同角色（如产品经理、程序员、测试员）分工协作，如 MetaGPT、斯坦福“AI 小镇”。优点是分工明确；缺点是要设计它们之间怎样沟通、怎样解决分歧，开发难度大（详见 5.3 节）。
- **具身智能体**：有实体“身体”的智能体，如人形机器人。例如 2024 年 Figure 公司演示的人形机器人能听懂“我想吃点东西”并递上苹果。最大的挑战是莫拉维克悖论：让 AI 下围棋容易，让它像人一样叠衣服却很难（详见 5.4 节）。

**3. 教育领域的应用**

智能体正在尝试回答一个教育难题：怎样在老师精力有限的情况下，做到更多的“因材施教”？我国有专任教师约 1890 万人，批改作业、统计学情等重复性工作占用了老师不少时间。下面两个案例中的数据均为企业公布。

!!! example "案例 5-2 科大讯飞“星火智能批阅机”（企业公布）"
    - **识别笔迹**：针对学生手写的、字母数字混合的数学作答，专门优化了手写识别模型。
    - **定位薄弱点**：借助学科知识图谱，从错题定位到背后的知识点。例如一道“一元二次方程”题做错了，可能是因为“因式分解”没掌握好。
    - **个性化反馈**：生成个性化评语，并推送几道同类型的变式题。

    据企业公布的试点数据，使用后每个班的人工批改时间大幅缩短，学生的错题解决率也有所提高。这类工具的定位是帮老师“减负”，把精力留给教学设计和师生交流，而不是代替老师。

    ![图 5-5 星火教师助手作业批改闭环](images/fig5-5.png){ loading=lazy }

    图 5-5 星火教师助手作业批改闭环
    { .fig-caption }

!!! example "案例 5-3 作业帮：拍照搜题的三代演进（企业公布）"
    - **第一代：文字识别 + 题库匹配**。识别题目文字，在题库里找相似的原题。题目稍作改动就搜不到，几何图形也认不出。
    - **第二代：深度学习 + 公式识别**。能识别手写公式和几何图形的结构，准确率提高，但仍然主要靠“找原题”。
    - **第三代：多模态大模型 + 智能体**。能同时“看懂”图形和文字条件，分步引导学生解题；再借助知识图谱定位薄弱点，推荐讲解视频和变式练习。

    这个案例说明：垂直领域的智能体，竞争力往往不只在模型本身（大家都能用上不错的模型），更在于**积累的专业数据和对业务流程的理解**。

    同时也要想一想：分步引导解题，是在帮学生学会，还是在帮学生“抄得更方便”？工具的设计和使用方式决定了答案。

## 5.1.5 智能体的“技能” {#515}

**1. 什么是技能（Skill）**

智能体不仅要“会用工具”，还要“懂行”。就像医生要掌握手术规范、会计要熟悉记账流程一样，智能体也需要特定领域的“操作手册”。

2025 年 10 月，Anthropic 推出了“智能体技能”（Agent Skills），同年 12 月将其作为开放标准发布。一个技能就是一个文件夹，里面有一份说明文件（SKILL.md，写清楚这个技能做什么、按什么步骤做），还可以附带脚本、模板等资料。**技能不需要训练模型**，是人（或者 AI 协助）编写的说明书。

**2. 技能的特点**

- **按需加载**：智能体平时只看到每个技能的简短介绍，遇到相关任务时才读入完整说明，节省上下文空间。
- **可复用**：同一个技能文件夹可以在不同的项目、不同的人之间共享。
- **专业聚焦**：把某个领域的专家经验、标准操作流程（SOP）写进去，比如“按学校格式排版毕业论文”“生成符合公司规范的周报”。

表 5-3 技能与普通工具调用的区别
{ .tab-caption }

| 维度 | 普通工具调用 | 技能 |
|---|---|---|
| 是什么 | 一个可以执行的功能（如查天气） | 一份说明书，告诉智能体怎样完成一类任务，可以附带脚本和模板 |
| 复杂度 | 单一功能 | 多步骤流程（如“写一份财报分析”） |
| 专业性 | 通用 | 内置领域经验和标准流程 |
| 组合性 | 有限 | 一个技能里可以用到多个工具 |

!!! warning "技能也有安全风险"
    技能可以带脚本，智能体加载技能时也会执行其中的指令。来路不明的技能包可能藏有恶意代码或“提示词注入”（见 7.2 节）。只安装可信来源的技能，安装前看一看它的说明和脚本。
