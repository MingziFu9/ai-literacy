# 3.7 深度实战演练 {#37}

!!! info "学前导读"

    本节给出三个“拿来就能用”的实战案例：读论文、写小说、做小游戏。不要求你全部做完，挑一个和自己专业最相关的跟着做一遍即可。三个案例都可以用国产大模型完成（如 Kimi、豆包、DeepSeek、通义千问）。

    做的时候记住两条：**AI 是助手，你是作者和最终责任人**；**交作业时要按老师的要求说明 AI 用在了哪里**。

## 3.7.1 学术科研——全能论文阅读助手 {#371}

!!! example "案例 3-3：AI 科研助理搭建"

    **场景**：快速阅读一篇较长的论文（中英文均可）。

    **工具**：支持上传 PDF 的国产大模型，如 Kimi、豆包、通义千问。

    **提示词设计**：

    ```text
    你是一位有 10 年经验的研究员。请阅读附件论文，并按以下结构输出总结：
    1. 一句话总结（这篇论文解决了什么问题）
    2. 核心创新点（和以前的研究相比新在哪里）
    3. 方法（用了什么数据、什么方法）
    4. 实验结果（在什么数据上，提升了多少）
    5. 批判性思考（从同行的角度看，有哪些不足）
    每一条都请注明出自论文的哪一节或哪一页。
    ```

    **使用要点**：

    - 让它“注明出处”，再亲自翻到对应位置核对，尤其是数字；
    - 总结只是帮你“快速了解”，引用论文观点时要读原文；
    - 不要让 AI 替你写论文的正文。

## 3.7.2 长篇创作——AI辅助小说撰写 {#372}

写长篇小说最难的是统筹。AI 不是打字员，而是你的“策划助理”。

!!! example "案例 3-4：科幻小说《硅基黎明》创作流"

    1. **世界观设定**：“请设计一个赛博朋克背景下的未来上海，包含核心冲突（人与 AI 的恋爱是否合法）、三大势力（反抗军、巨型企业、AI 教派）和力量体系。”
    2. **大纲生成**：“基于上述设定，生成一份 10 万字小说的 20 章大纲，结构符合‘英雄之旅’模型。第一章要有激烈的追车戏作为开场钩子。”
    3. **角色设计**：“为主角‘林 07’建立人物档案：性格、口头禅、童年经历、随身物品。”
    4. **正文撰写**：“根据第一章大纲，写一段开篇，风格冷峻、注重科技细节，重点描写雨夜霓虹灯下的追逐。”

    **使用要点**：AI 生成的内容往往套路化，最有价值的是用它来**头脑风暴、检查情节漏洞、保持人物设定前后一致**；真正打动人的细节和情感，还要靠你自己写。如果把作品拿去投稿或参赛，要遵守平台对 AI 生成内容的规定。

## 3.7.3 全栈开发——从贪吃蛇到塔防游戏 {#373}

不要只用 AI 写“Hello World”。今天的大模型已经能帮零基础的人做出一个能玩的网页小游戏，关键是**分步迭代**。

!!! example "案例 3-5：塔防小游戏开发"

    **目标**：开发一款网页版塔防游戏，包含防御塔、敌人波次和血条。

    **提示词策略（分步迭代）**：

    1. **V1 原型**：“用 HTML 和 JavaScript 写一个最简单的塔防游戏，所有代码放在一个文件里。点击地图放置防御塔（红点），敌人（绿点）从左向右移动，防御塔自动攻击。”
    2. **V2 机制**：“增加金币系统：消灭敌人得 10 金币，建造防御塔花 50 金币。敌人沿一条弯曲的路径移动。”
    3. **V3 美化**：“把红点换成炮塔图形，绿点换成小怪物，加上爆炸效果。”
    4. **V4 排错**：“检查代码中的 bug；游戏结束时显示得分和‘再来一局’按钮。”

    **怎么运行**：把 AI 给出的代码保存成 `game.html` 文件，用浏览器打开即可。出错时，把浏览器报的错误信息原样复制给 AI，让它修改。

    **成果**：编者按这个流程，在不到一小时里得到了一个几百行代码、能正常游玩的小游戏。对零基础的同学，这是体会“用自然语言编程”最直观的方式。

- B. 代码报错后直接放弃
